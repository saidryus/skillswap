Topology Characteristics
Characteristic Value Notes
Topology Type Star All internal nodes communicate exclusively through the Express.js backend hub. No direct node-to-node connections exist within the system.
Central Hub Express.js Backend (Node.js) Routes all requests, handles authentication, controls access to the database and ML services.
Client Nodes 3 browser roles (Student, Tutor, Admin) All run the same React SPA. Role-based access controls differentiate capabilities.
Database Node MongoDB Not internet-facing. Accessible only by the hub (Express.js). Student data never leaves the institutional network.
ML Service Nodes Flask :5002 and Flask :5003 Two internal-only microservices. Receive requests only from the hub. Not reachable by the browser directly. ML Service 1 (port 5002) handles recommendation letter analysis; ML Service 2 (port 5003) handles tutor feedback sentiment.
External Exception Jitsi Meet (meet.jit.si) The only node outside the star. Browsers connect directly via HTTPS. The backend has no visibility or control over this connection — which is why recording cannot be enforced.
Real-time Communication N/A In-session chat uses standard HTTP REST (POST to send, GET to fetch). There is no persistent WebSocket connection.
Deployment On-premise (Institutional) Backend, database, and ML services run within the institution's network. Supports privacy-first architecture — no student data transmitted to external servers.
Note on Jitsi Meet: Jitsi Meet is the only external dependency in Acadia's topology. The browser establishes a direct HTTPS connection to meet.jit.si without routing through the institutional backend. This is an intentional design choice that enables free, open-source video conferencing without infrastructure cost. However, it means the system has no control over the video stream or recording. Users who wish to record sessions must use Jitsi's built-in recording feature or external screen recording tools, and may share the resulting link through Acadia's in-app session chat.
